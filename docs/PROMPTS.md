# Промты реализации VolleyPlay

Актуальный пакет находится в [`docs/implementation-prompts/`](implementation-prompts/README.md).

Он содержит **100 последовательных непересекающихся промтов**, пронумерованных `000–099` и адаптированных для Codex с установленным iOS-плагином.

## Первые шесть запусков

1. `000` — базовый запуск Codex, определение фактического @-упоминания iOS-плагина, Expo и Supabase baseline;
2. `001` — основа вкладки `Профиль`;
3. `002` — основа вкладки `Игры`;
4. `003` — основа вкладки `Чаты`;
5. `004` — основа вкладки `Кэмпы`;
6. `005` — основа вкладки `Настройки`.

После них приложение должно запускаться, показывать пять вкладок, базовые переходы и честные состояния незавершённых функций.

## Категории

1. `01-foundation.md` — `000–009`: запуск, пять вкладок, UI и Router;
2. `02-auth-actors.md` — `010–019`: Supabase, Auth и actor-профили;
3. `03-shell-profile-catalog.md` — `020–029`: профиль и личные разделы;
4. `04-games-public-create.md` — `030–039`: база игр, каталог и создание;
5. `05-games-management-formats.md` — `040–049`: страница игры, управление и игровые форматы;
6. `06-games-audit-trainings.md` — `050–059`: тренировки и два турнирных формата;
7. `07-chats-payments.md` — `060–069`: чаты, уведомления и платежи;
8. `08-camps-organizations.md` — `070–079`: кэмпы и организации;
9. `09-backend-integration.md` — `080–089`: migrations, RLS, cache, security и iOS screenshots;
10. `10-quality-release.md` — `090–099`: тесты, builds, TestFlight readiness и release candidate.

## Правила запуска

- Сначала выполнить `000`, который записывает реальное имя iOS-плагина в `docs/IMPLEMENTATION_RUNTIME.yaml`.
- Затем выполнить `001–005` строго по порядку.
- Один промт — один узкий результат и один логический commit.
- Перед изменением проверять фактическое состояние и не переписывать уже работающую реализацию.
- `partial`, `placeholder`, `definition_pending` и `blocked` не маскируются под готовую функцию.
- После каждой категории выполнять её `Audit-only` промт.
- Backend первого прохода: Supabase Postgres/Auth/Storage/Realtime, Edge Functions для секретов и Expo SQLite для локальной сессии/cache.
- Не возвращать сезоны, круговую или швейцарскую систему, `Группы + плей-офф` и отдельный турнир `Король пляжа`.
- Не merge, не публиковать TestFlight/App Store build и не выполнять production migrations без отдельной команды пользователя.
